# What's new in v1.3.2, for someone upgrading from v1.3.1

This release brings the Linux panel level with the Windows one in how it moves and what it
offers. On Linux the panel now slides in and out, the "On this machine" block turns and its
table folds, the off-plan banner folds away, the bars rise and the rings sweep in, a second
tray click closes the panel, chart bars and model names show the same hover card the
doughnuts do, and the right-click menu gains "Notify at", "Weekly reset" and "Copy
diagnostics". **Nothing a user sees on Windows changed.** No Windows source file and no
sample picture differs from v1.3.1. Two package updates, listed under "Smaller things", reach
both platforms.

## Linux: the panel slides in and out

The panel's content now slides in from the edge it is docked to and back out, on the Windows
panel's figures and curves: 460 ms in and 300 ms out. The window itself stays where it was
put, because native Wayland refuses a client that moves its own window.

- **Where the desktop composites, only the card is drawn while it moves.** On a desktop that
  does not composite, the panel appears and goes at once, as in v1.3.1.
- **A tray click while the panel arrives or leaves turns it round** from where it is on
  screen, with no jump.
- **Your desktop's animation setting is respected.** O-view reads it through the XDG portal.
  With animations off, every change in this release lands in one step. If the setting cannot
  be read, animations are on.

## Linux: the block turns and the table folds

The flip tag turns "On this machine" between the totals and the models, and the Output |
Overall switch slides its highlight and folds the table, on the same figures and curves.

- **A second press in the middle of either carries on from what is on screen** instead of
  starting again.
- **A panel docked at the bottom keeps its lower edge where it was placed** while its height
  changes, as the Windows panel does.

## Linux: the banner folds away, the bars rise and the rings sweep in

- **The off-plan banner fades and folds away** when you hide it with the ×, and the panel
  closes up over the gap.
- **The chart's bars rise** as the panel opens and when the block turns back to the totals.
- **The doughnuts' rings sweep in** when the panel opens on the models or turns to them.
- **An Output | Overall press moves every bar together** from its old height to its new one.
- **Hiding the banner, a refresh or any other redraw replays nothing.** The arrival plays
  only when the panel opens and when the block turns.

## Linux: a second tray click closes the panel

Clicking the tray icon while the panel is open now closes it, as on Windows.

- **The click that took the focus away is counted as the close.** A click within 400 ms of a
  close caused by the panel losing focus is the second half of the toggle, so the panel no
  longer flashes away and straight back.

## Linux: the banner's × takes the keyboard

The × that hides the off-plan banner can now be reached with Tab. Enter and Space hide the
banner for good, exactly as a click does.

## Linux: chart bars and model names show the hover card

Hovering a bar of the 31-day chart, or a model's name in the table, now opens the same card
the doughnut sections use, in place of the plain tooltip text.

- **A bar's card is laid out like the Windows one:** the figure large, with its day muted
  beneath.
- **A model name's card carries the full id**, wrapping where the table trims it.
- **Every card ends inside the panel.** A bar's card follows the pointer while it fits to the
  right of the bar, and opens on the bar's left after that.

## Linux: the right-click menu gains three rows

- **"Notify at"** opens a submenu with 70%, 80%, 90% and "Off", with the setting in effect
  ticked. "Off" is listed beside the percentages, because a desktop-drawn menu cannot put a
  tick on the row that opens a submenu. The tick shows what O-view saved, so a settings write
  that failed never shows as saved. A threshold you edited into `settings.json` by hand, say
  75, gets its own ticked row reading "75%".
- **"Weekly reset..."** shows "derived" or the day and time you entered, and opens a small
  dialog where you enter the weekly reset Anthropic assigned your account. It follows the
  Windows rules: an empty time clears the entry, and a reset that Claude later reports and
  that disproves your entry is announced once, in the Windows words.
- **"Copy diagnostics"** puts the same support bundle on the clipboard that Windows copies,
  with no window, plus the Linux machine details: desktop, session type, install kind and the
  tray host check. A notification says it was copied, or that it could not be.

## Smaller things

- **Avalonia, the Linux toolkit, moves from 12.1.5 to 12.1.6**, and **Microsoft.Data.Sqlite
  from 10.0.14 to 10.0.15.** The Sqlite update is in the shared code, so Windows has it too.
  Both are version bumps and nothing else changed in them.
- **The build pipeline's .NET setup step is updated** from `actions/setup-dotnet` 6.0.0 to
  6.1.0. It changes how releases are built, not what they contain.
- **The documentation says what Linux now does.** The architecture page, the UI spec, the
  overview and the README were updated, and the feature checklist rows F16 and F59 no longer
  say Linux lacks what it now has.
- **`docs/platform-status.md` records the Linux sign-off** described below, and no longer says
  Linux has no motion.

## What's known not to work, or hasn't been checked

- **Maximilian signed off a test build of this code on an Ubuntu 24.04 VM on 2026-11-11, with
  one Yes to a card of checks.** The test build was `1.3.2-trial.2`, built from `main` with
  both package updates in it. Since then only `docs/platform-status.md`, the README and
  these notes changed, so no code differs from what he tested. He confirmed he stopped the old copy, installed the build and saw the
  version line say `1.3.2-trial.2`. The card asked him to check that the panel slides up out
  of its edge and back, that a second tray click closes it, that the block turns and the
  switch folds the table without the panel jumping, that the bars rise and the rings sweep in,
  that a chart bar and a model name show a card, that the menu has the three new rows, and
  that with animations off in the Ubuntu settings all of it still works and nothing moves. The
  Yes covers the card as a whole. He wrote no notes, and nothing records which items he tried
  or what each one showed.
- **The banner's × and its keyboard route are not called seen.** The card asked for them only
  if his account showed the off-plan banner, and nothing records that it did. Tests send the
  keys to the control, and Avalonia moves no focus without a windowing subsystem, so Tab
  reaching the × has not been driven on any machine.
- **Nobody has run this on a physical Linux desktop.** Every observation of the panel, motion
  included, is from the VM. The VM's session type, display scale and whether the pointer was
  real are not recorded, and no display scale other than the VM's has been seen.
- **Nobody has installed the published v1.3.2 packages.** The sign-off was on a test build
  from the release pipeline, not on the release.
- **The portal's animation setting was written from its specification.** GNOME publishes its
  key through the portal. The key name and value type Plasma uses, and whether its portal
  version has `reduced-motion`, were not seen on a machine. A key that is missing reads as
  animations on.
- **What a window manager draws around the see-through panel while the card moves is not
  seen** on GNOME or Plasma. A frame or shadow at full size would still show. On a desktop
  without compositing there is no motion, and the panel appears at once.
- **On X11 a frame of a fold is a resize and a move.** Whether a window manager draws them as
  one step or shows a one-frame jump is not known. A manager that refuses the move leaves the
  lower edge moving during the fold.
- **Whether KDE or GNOME under XWayland deliver the focus loss more than 400 ms before the
  tray click was not measured.** If one does, the click reopens the panel as before this
  release.
- **Where a hover card lands is computed, not observed.** Its place comes from the panel's
  layout and the card's measured size, as the doughnut's cards were. The sign-off card asked
  him to hover a bar and a model name, so the card appearing is covered by his Yes. Its
  placement at the panel's edges is not recorded.
- **The menu rows' actions are covered only by the sign-off's check that the rows are there.**
  The card asked for the rows, the tick on the setting in use, and the small window the weekly
  reset row opens. No automated test clicks a menu row over D-Bus, so the clipboard write runs
  only on a desktop, and nobody has recorded pasting a diagnostics bundle or a tick moving in
  the submenu. Before the VM, the "Weekly reset" dialog was shown only in a Windows-backed
  Avalonia window, in both themes.
- **The Linux head's runtime tests run only in CI,** not in `tools/check.ps1`. That includes
  the menu's rows, the tray toggle and the first window to run the motion.
- **A pointer press on the banner's × is not raised in a test,** because a test has no
  pointer. The test runs the same hide as Enter and Space, which are both tested.
- **Hover text on the off-plan row is still plain black on white** and no sample picture shows
  a hover card on Linux. The Linux panel registers no theme, so a tooltip is not styled.
- **A very long model name's wrap in the Linux panel has no test,** and the Linux model limit
  bar has been seen only in rendered images.
- **Not re-checked in this release:** Windows. Nothing in it was aimed at the Windows panel,
  and its sample pictures are unchanged, but no one ran the Windows panel again for v1.3.2.
