# What's new in v1.0.0, for someone upgrading from v0.9.7

Most of the work between those two releases was internal, moving code around without
changing what you see, so this page only covers the parts you would actually notice.
If you're on Windows, most of this is new only to Linux, catching it up to what Windows
has always done; a few things are new everywhere.

## The Linux detail panel now shows what the Windows one does

However you open it, a double-click on the Linux tray icon, **Show usage** from its
menu, or a left-click on Windows, the panel now shows the same things on Linux as it
always has on Windows:

- **The four stat tiles flip.** Click one of the four usage tiles and it turns into a bar
  broken down by model, with per-model figures on hover. Click it again to flip it back.
- **The 31-day usage graph has reset lines and hover cards.** Once O-view has seen your
  plan's weekly reset, dotted lines mark it; until then they mark the calendar week's
  Monday boundary instead, and the graph says so rather than guessing. Hovering a day
  shows its figures in a card.
- **Off-plan usage has its own banner and section.** If some of your usage is billing as
  extra rather than drawing from your plan, the panel says so and shows an estimated
  value for it, the same way it does on Windows.
- **The "Bars/Breakdown" switch has its two words.** The control that flips the "Tokens
  used" section between a bar view and a table view used to render blank on Linux; it now
  shows the same two labels Windows does.

## The panel can now be moved, on both platforms

This is new everywhere, not just on Linux, the panel used to always open in the same
corner, full stop.

- **Drag it by its header**, and it reopens in the same place next time.
- **Alt and an arrow key move it**, a step at a time, or Alt+Shift for a single pixel,
  without needing the mouse.
- **A new "Reset panel position" row**, in both the Windows and the Linux menu, puts it
  back in the corner and forgets where it was.
- On Linux this only works in an XWayland or X11 session. A native Wayland session has
  no way to set or remember a window's position, so there the panel always opens in the
  work-area corner and the menu has no reset row.

## The panel fits a short screen

If the panel would be taller than the screen, it now stops at the edge of the usable area
and scrolls instead of running off the bottom or getting cut off. The mouse wheel scrolls
it from anywhere over the panel, not just over one particular part of it.

## The Linux menu leads with the panel

Right-clicking the Linux tray icon now shows **Show usage** as the first row. Opening
the panel itself has always taken a double-click, nothing on screen ever suggested
that, so the menu now offers an obvious way in instead. The full order is Show usage,
Reset panel position, Run at startup, Exit O-view.

## The usage bars are more honest about where they come from

The session and weekly usage bars, and the messages O-view shows when it has no data,
used to sometimes name one particular source for your numbers, even on a machine where
a different source was the one actually used. They now name only a source O-view
genuinely read, or say plainly that they don't know, rather than guessing.

## No more false "nowhere to show the icon" warning at login

On Linux, O-view used to check for the desktop's notification area a little too early at
login, before the desktop had finished setting it up, and would wrongly tell you it had
nowhere to put its icon even though one was about to appear. That check now waits for the
real answer, so the warning only appears when it's true.

## Two smaller accuracy fixes

- **O-view's own background usage check no longer counts as your own usage.** O-view
  periodically asks Claude Code to refresh its usage figures in the background; a bug
  meant that this background check itself could be counted alongside your real activity.
  It's now left out.
- **The weekly reset time no longer shows as "unknown" when O-view actually had it.**
  A bug meant the panel could report that no weekly reset time had been found, while
  quietly still holding one. The two now agree.

## What's known not to work, or hasn't been checked

- **The very first Alt+arrow press right after clicking the panel's header does
  nothing.** The presses after that one move the panel as expected. This is a known,
  minor defect, not something to retry endlessly if it doesn't seem to respond once.
- **Only part of the above was checked on an actual Linux session, and that session was
  Wayland (through XWayland).** The tile flip, the graph's hover card, the off-plan
  section and the Bars/Breakdown words were. The per-model figures on a tile's hover
  card, the graph's weekly-reset lines, and the off-plan banner itself were not checked
  separately and are not yet confirmed there.
- **An Ubuntu session on Xorg has not been re-tested against the Linux fixes in this
  release.** It was last checked on 2026-10-15, against an earlier build, before most of
  the Linux work above existed.
- **Nobody has opened the detail panel on a physical Linux desktop.** Every Linux check
  behind this page, including everything above, was run on an Ubuntu 24.04 virtual
  machine, not on real hardware.
