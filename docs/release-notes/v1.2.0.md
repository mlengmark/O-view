# What's new in v1.2.0, for someone upgrading from v1.1.0

This release is about accounts that have a weekly limit on one model, such as Fable on Max.
That limit now has its own bar, and usage that draws from it is no longer counted as
off-plan. The off-plan section also got quieter for everyone: it is not drawn at all until
there is something to put in it.

## A model's own weekly limit gets its own bar

If your account has a weekly limit on a single model, the panel now shows it as its own bar
under Weekly, named for the model, for example `Weekly · Fable`. It has its own percentage
and its own reset time, in the same colours as the other bars, on Windows and on Linux.

The bar is read from the figures Claude Code keeps on your machine, so it needs Claude Code
to have run on this account. A figure whose reset time has already passed reads as unknown
rather than showing the old percentage. An account with no such limit sees no bar and no
empty space where one would be.

## The off-plan section shows only what fell outside the plan

- **It is hidden until there is off-plan usage.** With nothing to show there is no heading,
  no `$0.00` and no gap. This is true on every account and on both panels.
- **On an account with a model limit, it shows what Claude reports as spent.** Usage of
  that model draws from its own limit, so O-view no longer prices it as if it had been
  billed. The section shows the amount Claude itself reports as spent past the plan,
  labelled as reported, with no `Est.` in front and no claim about which days it covers.
  While that amount is zero the section stays hidden, however heavily the model was used.
- **On every other account it is the estimate you had before,** over the same window as the
  graph, still labelled `Est.`.
- **The two figures are never added together or shown side by side.**
- **Unknown is said as unknown.** If extra usage is switched on and no amount can be read,
  the section says the amount is unknown rather than showing zero.

## Ordinary usage is less often mistaken for off-plan

The check behind the off-plan banner compares your work with the five-hour window it
believes is running. It used to work that window out from Claude Desktop's samples alone,
and when Desktop was closed as a window began, the guess could be hours too early and make
ordinary usage look as if it was not drawing from the plan. The check now takes the window
Claude Code reports whenever it reports one, and falls back to the old method only when it
does not.

## Linux: one tray icon, and the theme follows at once

- **One icon, not two, when the tray comes back.** Switching the AppIndicator extension off
  and on again while O-view was running could leave two O-view icons. O-view now asks the
  tray what it already lists before showing its icon again.
- **A light or dark switch shows on the very next panel open.** It used to take one more
  open before the panel caught up with the desktop.

## Smaller things

- **The tooltip and the panel show the session reset the same way.** The tooltip never
  printed the `~` that marks a reset time as approximate, while the panel did. Both now
  take the time from one place.
- **Bug reports say more, and raise fewer false alarms.** The diagnostics report now states
  what it found for a model limit and for reported spend, and says so when Claude Desktop
  and Claude Code disagree about the session window, which usually means they are signed in
  to different accounts. It no longer lists O-view's own usage refreshes as files that
  produced nothing.
- **The Linux log no longer calls the missing-GPU fallback an error.** On a machine without
  a usable GPU the panel is drawn on the CPU, which works, and the log now says so calmly.
- **Two libraries moved to their maintenance releases.** The Linux head takes Avalonia
  12.1.5 and both heads take Microsoft.Data.Sqlite 10.0.14. Neither changes behaviour.

## What's known not to work, or hasn't been checked

- **A reported spend above zero has never been seen on a real account.** Only zero has. The
  amount shown in that case, and any currency other than US dollars, rest on tests and on
  the names of the fields Claude Code writes.
- **A reported amount under half a cent would show as `$0.00`.** It is a rounding of a real
  amount, not an invented zero, and no account has shown one.
- **The model bar was checked on one real account, on Windows.** It was compared with
  Claude's own usage page on a Max account with a Fable limit. On Linux it has been seen
  only in the rendered images the test suite compares, and how the Linux panel wraps a very
  long model name has no test.
- **The two Linux fixes were not run on a real desktop.** The single tray icon and the theme
  switch are proven by tests and by CI's headless Linux job with a real session bus, not by
  a person at a GNOME desktop.
- **The very first Alt+arrow press right after clicking the panel's header still does
  nothing.** Nothing in this release touched it. The presses after that one move the panel
  as expected.
